# AGENTS.md — audiobook

Этот файл — для любых AI-агентов/инструментов, которые понимают конвенцию
AGENTS.md (не только Claude — см. также `CLAUDE.md`, он для Claude Code/Cowork
специфично и местами подробнее). Если оба файла есть — считайте `CLAUDE.md`
более полным источником для инструментов линейки Claude, а этот — общий минимум.

## Что это

FB2 → аудиокнига на русском. GUI на Tkinter + несколько TTS-движков, часть из
которых — REST-сервисы, которые GUI сам поднимает как подпроцессы на голом
Windows (без Docker — решение окончательное, не предлагать вернуть Docker).

## Ключевые файлы

| Файл | Роль |
|---|---|
| `fb2_reader_gui.py` | GUI, вся оркестрация озвучки и REST-сервисов |
| `fb2_reader.py` | парсинг FB2, разбиение на фрагменты, вызовы TTS |
| `cosyvoice_rest_service.py` | REST на порту 5011: F5-TTS / ESpeech RL-V2 / XTTS-v2 |
| `cosyvoice3_rest_service.py` | REST на порту 5012: CosyVoice3, отдельный venv |
| `silero_rest_service.py` | REST для Silero |
| `install.bat` | ставит все venv-окружения и веса моделей |

## Правила изменений

- Не удалять и не менять логику ESpeech RL-V2 (порт 5011) без явного запроса —
  подтверждённо хорошо работает для русского.
- Каждый `*_rest_service.py` несёт `SERVICE_VERSION`; GUI сверяет её с
  `..._EXPECTED_SERVICE_VERSION` в `fb2_reader_gui.py`, чтобы решить, перезапускать
  ли уже работающий процесс. При любой правке сервиса — бампать версию в ОБОИХ
  местах, иначе GUI «усыновит» старый процесс со старым кодом (наблюдалось
  многократно на практике).
- `cosyvoice3_rest_service.py` существует в двух копиях на диске:
  `C:\Users\user\audiobook\cosyvoice3_rest_service.py` (эталон) и
  `C:\Users\user\audiobook\CosyVoice3\cosyvoice3_rest_service.py` (то, что реально
  запускается) — обновлять обе.
- После правки сервиса пользователю нужно не просто перезапустить GUI, а убить
  процесс на нужном порту (`netstat -ano | findstr :5012`, `taskkill /F /PID ...`)
  — иначе изменения не подхватятся.
- Не коммитить `fb2_reader_settings.json` / `dialogue_characters.json` (секреты,
  данные конкретного прогона) — уже в `.gitignore`.

## Особенности CosyVoice3 (порт 5012), проверено практикой

- Чекпоинт `CosyVoice3LM` требует токен `<|endofprompt|>` в
  `prompt_text + text`, иначе `AssertionError` на каждом вызове. Правильный
  формат: `"You are a helpful assistant.<|endofprompt|>" + <реальный
  транскрипт образца>` (маркер между вводной фразой и транскриптом).
- Длина образца при обрезке (`MAX_PROMPT_SECONDS`) и длина окна распознавания
  транскрипта (`MAX_TRANSCRIBE_SECONDS`) должны совпадать — иначе текст
  описывает больше аудио, чем реально есть в обрезанном образце.
- Публичный `inference_zero_shot()` сам ре-режет входной текст на предложения —
  если текст уже порезан вызывающим кодом, вызывать внутренние методы
  `frontend`/`model` напрямую, а не публичный API.

## Как отлаживать

Логи (`fb2_reader_gui.log`) накапливаются за весь день без ротации — при
разборе смотреть последний прогон по временным меткам, не первые совпадения
grep по всему файлу. При непонятном поведении TTS-движка — читать исходники
движка на месте, а не полагаться на память/документацию: почти все реальные
причины багов в CosyVoice3 нашлись именно так.
