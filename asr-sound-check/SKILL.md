# Проверка звука по ASR и автопочинка (Silero REST)

Подробности про природу гула и историю расследования — в `tts-audio-artifacts/SKILL.md`. Здесь — как это устроено в программе и как этим пользоваться.

## Что есть
| Что | Где |
|---|---|
| Автопочинка при озвучке | `asr_autorepair.py` (`AsrRepair.check_and_fix`), вызывается из `run_silero_rest` → `synth_chunk`; флаг CLI `--asr-repair`, галочка GUI «Автопочинка по распознаванию» (**вкл. по умолчанию**, `asr_repair_var` в `SETTINGS_FIELDS`) |
| Воркер распознавания | `tools/asr_worker.py` — отдельный процесс в `.venv_cosyvoice3` (openai-whisper, CUDA), протокол JSON-строк `@@...` |
| Строка статуса | вкладка «Озвучка», под галочкой: `asr_status()` → зелёный `medium` / жёлтый `small` / серый «нет окружения» |
| Окно «Проверить звук готовых глав…» | `gui_audio_check.py` (`AudioCheckMixin`): скан целых глав → таблица глава/время/тип/услышано; ▶ послушать место (клип ±3…4 с), «Пересинтезировать главы с дефектами (с автопочинкой)», CSV |
| Сводка | после каждой главы в журнале: «ASR-проверка гл.N: кусков X, с дефектом Y, исправлено Z, осталось W»; итог и отчёт `<outdir>\asr_repairs.jsonl` (с SSML) |
| Установка | `install.bat` → `tools\fetch_whisper_model.py medium` (докачка, SHA-256, таймауты, не фатально); без модели воркер берёт `small` |
| Сборка .exe | `main.spec`: `tools/asr_worker.py`, `tools/asr_cache_cuda.py` кладутся как файлы (`resolve_asset`), окружение `.venv_cosyvoice3` — рядом с .exe; `gui_audio_check`, `asr_autorepair` в hiddenimports |

## Как работает проверка куска
1. Кусок синтезирован → воркер распознаёт его → `chunk_defects(src, words, kinds=…)` (сверка по `difflib`).
2. Дефекты: `hum` («ммм/аммм/аааа», которого нет в тексте), `stretch` (слово >2,5 с, кроме заголовка 1-го куска), `missing` (≥8 слов проглочено), `gap` (пауза между узнанными словами дольше нормы по знаку: нет 0,35 / запятая 0,75 / предложение 0,95 / абзац 1,35 с; пороги — 99,9-й перцентиль 168 тыс. пауз 50 глав `sample_book`).
3. Лечение по порядку (`tweaks_for`): убрать паузу перед словом → **раздельный синтез повреждённого предложения** (два запроса + `join_wavs`) → темп −5 → без пауз на запятых → без `<prosody>` эмоции → … → вырезание гула из звука (`cut_spans`/`voiced_spans`, принимается только если ASR подтвердил). Побеждает вариант с меньшим числом дефектов; нет лучше — остаётся исходный.
4. Скан целой главы (`scan_chapter`, окно GUI): то же по всей главе, первые 14 с (заголовок) без вердиктов; запись «ммм» словом у Whisper на целой главе стабильнее, чем на куске. **Модель для целых глав — `small`** (`CHAPTER_SCAN_MODEL`): на 25-минутном файле `medium` пропускает куски текста (27 ложных «проглочено» в гл. 36 и не нашла гул 3:55 в гл. 28); `small` на целой главе проверена (гл. 28: гул 3:55 и новый 12:34, гл. 36: чисто). Для отдельных кусков при озвучке — `medium` (на коротком звуке точнее таймстемпы).

## Скорость и числительные (21.10.2026, поздний вечер)
- **Конвейер.** Проверка куска N идёт в фоне (`AsrRepair.submit`, пул потоков + 2 процесса-распознавателя, `AUDIOBOOK_ASR_WORKERS`), пока Silero синтезирует N+1; результаты разбираются по порядку (`_AsrPending`, `finish_pending`), запросы к Silero сериализует `_silero_lock`. Замер (гл. 1, 44 куска): 4:09 (5,7 с/кусок) против ≈3:00 без проверки и ≈7 мин при последовательной проверке. Узкое место — декодирование whisper (medium ≈5,4 с на 30 с звука, GPU при этом простаивает: мелкие запуски ядер; два процесса делят GPU по времени → ≈4,3 с/кусок суммарно). Silero работает на CPU (4 потока, квантованная модель `ru_emph_q`, на GPU не пойдёт).
- **Цена безуспешной починки** ≈ попытки × (синтез ≈4 с + ASR ≈5 с): лестница ограничена 4 попытками (`max_attempts`) + вырезание гула.
- **Числительные детектор не сравнивает вообще** (`_NUMERAL_RE`, `_asr_without_numbers`): Whisper пишет «8 -м флотом», «23 минуты» цифрами (нормализация выбрасывает цифры → одинокое «м» и «пропуски»), а пауза рядом с числом включает само число. Проверено на 14 чистых клипах: Silero числительные читает ПРАВИЛЬНО (Whisper возвращает те же числа). Ложные срабатывания, которые это убрало: «м флотом», «часов (0,4 с) минуты», пауза заголовка главы («глава (1,3 с) глава»).
- **Реальный дефект был в программе:** цифры с суффиксом («5019-м батальоном», «1909-й», «1901-го» — 3 места в книге) превращались в «пять тысяч девятнадцать м» и читались «…эм»; теперь `numbers_to_words_ru` строит порядковые слова (`_ordinal_words_ru`: «5-го» → пятого, «5019-м батальоном» → пять тысяч девятнадцатым, «в 1990-е годы» → девяностые; «м» — творительный/предложный по соседним словам). Главы с этими числами затронуты → пересинтез.

## Что вскрылось в живом GUI (21–22.10.2026)
- **Озвучка «очень медленная, GPU 25 %, CPU пуст»** = каждый кусок ждал 180 с. Причина: процесс GUI без UTF-8-режима, воркер (`tools/asr_worker.py`) писал кириллицу ответа в cp1251, поток чтения `AsrWorker._read` падал с `UnicodeDecodeError`, ответы терялись, `transcribe` ловил `queue.Empty`. Симптом в журнале: `asr_repair гл.N фрагм.M: проверка пропущена ()` с ПУСТЫМ текстом ошибки (пустая скобка = таймаут очереди) + `ОШИБКА (фоновый поток … _read)`. Из консоли Claude это не воспроизводилось, потому что там включён UTF-8. Лечение: воркер отвечает `ensure_ascii=True`, клиент `errors="replace"`, `_read` в `try/finally` всегда шлёт `@@eof`. Проверять воркер ТОЛЬКО с `env -u PYTHONUTF8 -u PYTHONIOENCODING`.
- Журнал GUI — `logs\fb2_reader_gui.log` (не в корне); он смешан с эхом сервиса Silero, фильтровать `grep -av getssml`.
- **Скан готовой главы показывал «то же место» после автопочинки.** Это была не гул-ошибка, а пауза абзаца 1,4 с (≈1,0 с тишины: стык кусков/абзаца), чуть выше `GAP_LIMIT_S["p"]=1.35`. Пересинтез детерминирован и даёт ту же паузу. Теперь `scan_chapter` не сообщает паузы абзаца < 1,6 с (99,9-й перцентиль). Пока автопочинка чинила другое место (гул «курортом ммм», фрагмент 11) — в журнале «исправлено 1» относится к нему, не к строке скана.
- Нумерация в журнале: `гл.N` в `asr_repair` и `главы [N]` — 1-based позиция в списке (N=2 → «Глава 1», файл `002_…`), как `--chapters`.
- **Плеер в окне проверки** (`MciPlayer`, Windows MCI через ctypes, без пакетов): открывает ВЕСЬ файл главы и встаёт за 3 с до места; ▶/⏸, ⏹, ±5 с, ползунок по всей главе, время. Раньше было `winsound.PlaySound` в потоке — без паузы/перемотки/остановки (вырезка клипа при этом была верной: на 340,3 с звучит именно «…назвать курортом»). Открытый MCI-файл держит handle: перед пересинтезом и при закрытии окна плеер закрывается (`_ac_release_player`), иначе файл главы не перезаписать.
- **Окно «Проверка звука»:** полоса прогресса + счётчик (`глав n/N · мест K · прошло · осталось ~`); при пересинтезе та же полоса зеркалит `_on_synthesis_progress` через `ac_on_synthesis_progress` (глава/фрагмент/%/ETA) и по окончании пишет «пересинтез завершён». Проверено на заглушке Tk, вживую — нет.

## Ограничения (честно)
- Гул хаотичен (~0,4 % кусков): детерминирован для входа, но ни одно свойство текста его не предсказывает. Поэтому схема «поймать и повторить», а не профилактика.
- Recall ASR-детекции < 100 %: Whisper `small` на отрезке куска иногда не пишет гул; `medium` лучше (даёт честные таймстемпы → ловится `gap`). Подмена слова «На то» → «Но-то» не ловится (неотличима от ошибок Whisper на именах).
- ASR **не** проверяет ударения.
- Автопочинка добавляет время (ASR на каждый кусок); GPU нужен и LLM (≈8 ГБ), и whisper (≈1–3 ГБ) — ComfyUI закрыть.

## Отладка
- ASR не запускается: `asr_status()` (нет `.venv_cosyvoice3` / нет `tools\asr_worker.py` / нет `.pt`); воркер пишет в stderr (`AsrWorker` скрывает его — для отладки запустить `tools\asr_worker.py` руками и подать `{"wav": "..."}` в stdin).
- **Не качать модели whisper на лету** (`medium` с сервера — часы). Брать `tools\fetch_whisper_model.py` или файл `~\.cache\whisper\medium.pt` (SHA-256 `345ae4da…`).
- Фоновые задачи (скан, прогон) — следить: лог/`.err`, CPU процесса, `nvidia-smi`; не ждать молча (см. память `feedback_watch_background_jobs`).
- Прогон главы из CLI: номера `--chapters` с 1 (предисловие = 1, «Глава N» = N+1); файл `NNN_*.wav`, NNN = индекс списка + 1. Для воспроизведения с эмоциями: `--smart-emotion --attribution-provider builtin` (иначе SSML не совпадёт).
- Тесты: `tools\test_accentuation.py` (разделы «asr repair», «sound check»), логика без Tk и без GPU.
- Править Python-файлы с обратными слешами через Edit/Write, не через `python - <<EOF` в Bash-инструменте (слеши схлопываются, в файл попадают NUL).
