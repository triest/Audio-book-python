# Проверка ударений по главам (сухой прогон)

Парный скилл к `stress-dictionary-audit` (там — разбор жалобы на слово и аудит словаря). Здесь — поиск новых ошибок по главам.

## Порядок

1. **Выбрать главы.** «Пара глав» — две главы, которые ещё не смотрели (смотри `git log --format=%s | grep -i "dry run"` и историю беседы). Раньше проверены: 10, 15, 20, 28, 35, 40, 45.
2. **Прогнать цепочку** (та же, что на озвучку: числа → словарь → silero-stress → шлюз → санитайзер):
   `.venv\Scripts\python.exe -I stress-chapter-review\dry_run_chapters.py <scratchpad> 20 45`
   Скрипт сам пишет `chN.txt` и `words_new.txt` (уникальные слова с «+», которых не было в прошлых прогонах той же папки; `words_seen.txt` накапливается — для «ещё по паре глав» используй ту же папку). Занимает 30–60 с на главу при первом запуске. Консоль Git Bash портит кириллицу — читай файлы через `Read`, не через stdout.
3. **Прочитать `words_new.txt` целиком** и сверить каждое слово с нормой. «+» стоит ПЕРЕД ударной гласной (`зам+ок` = замóк); `в+идела` и т.п. читаются буквально. Проверять и положение метки, и опечатки в книге (ошибка книги — не ошибка ударения). Для подозрительных слов: `re.escape` при поиске «+» в Python (иначе regex пуст и вывод пустой), контекст брать по тексту `chN.txt`.
4. **Доложить пользователю короткий список ошибок** (слово → как должно быть, контекст) и спросить, добавлять ли. Не добавлять в словарь, пока пользователь не ответил, кроме случаев, когда он уже сказал «добавь».
5. **Добавить в `forced_stress_words.json`** (Python `json.load`/`json.dump(ensure_ascii=False, indent=2)`; утверждение `значение.replace('+','') == ключ`; только формы, реально встречающиеся в книге — искать целыми словами через `fb2_reader.parse_fb2`, `grep` по fb2 ловит подстроки вроде «содержание»). Проверить `git diff --stat` — меняются только добавленные строки.
6. **Коммит** — только когда пользователь попросит: `git add forced_stress_words.json`, сообщение в стиле истории (`Stress dictionary: ... (found in chNN dry run)`) плюс строка `Co-Authored-By` из системного напоминания. Не коммитить `fb2_reader_settings.json` и `dialogue_characters.json`.

## Уроки из беседы (правила достоверности)

- Пользователь сам решает, что считать ошибкой. Дважды предложенные «исправления» оказались неверными или спорными: `велено → велен+о` — НЕ ошибка (модель была права, запись удалена); `повергла → повергл+а` — подтверждено. Если не уверен в норме — не добавляй, назови слово отдельно как «под вопросом» и спроси (так было с «брался», «заждался», «залился»).
- Не выдавать длинные списки «подозрительного»: только то, в чём уверен, плюс 1–3 слова под вопросом.
- Не использовать омографы в записях словаря (см. `stress-dictionary-audit`): форму добавлять, если у слова одно чтение.
- Озвучка в этой среде не запускается: ударение в аудио подтверждает только слух пользователя; после правки словаря перезапуск не нужен, затронутые главы пересинтезируются сами.
- Ответы — по-русски, коротко, без заверений «теперь точно заработает».
