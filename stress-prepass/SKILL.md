# Предпроход с ранжированием

Дополняет `stress-chapter-review` (ручной разбор глав), `stress-sample-book` и `stress-listening-session`.

## Что это
`stress_prepass.scan_prepass(chapters, ...)` — ОДНА проходка цепочки (`stress_dry_run`, как на озвучке, со словарями) по книге, затем сумма слабых признаков на слово:
`conflict` (расходится с корпусом) 3.0, `conflict_common` (то же у частого слова, ≥20 вхождений, одно чтение) 1.5, `unstable` 1.0, `name` 1.0, `unknown` 1.5, `ctxdiff` 0.5, `lowconf` (пословная модель silero-stress: p<0.5 → 2.0, 0.5–0.9 → 0.5, ≥0.9 → 0; `accentor._get_model_preds(list слов)[0]` — вероятности по гласным). Балл × (1 + 0.5·ln(вхождений)); порог `MIN_SCORE` 2.5, по умолчанию топ 400. Результат — «моменты» формата `stress_review` (kind="prepass", поля `score`, `signals`).
Это ЛИД для прослушивания, не вердикт: уверенные ошибки модели («кр+яжей») не находятся; верх списка забит частыми верными словами с омографами — смотреть имена и редкие слова.

## Замеры (обратная проверка на «Пепле победы»)
Цепочка без словарей, «положительные» = слова из `forced_stress_words.json`, чьё чтение цепочки отличалось (117). Выборка смещена (их находили в т. ч. по корпусу, вес conflict завышен). conflict 13% попаданий при фоне 4,6%; lowconf сам по себе ~0,2% (p 0,9–0,99 — шум); топ-400 ловит 51 из 117 (≈2,8× случайного). Число вхождений на долю ошибок не влияет. Веса подобраны на одной книге — при новой книге перемерять (скрипт: монкипатч `fb2_reader.load_stress_dictionary = lambda **k: {}` и `stress_questions.dictionary_words = lambda *a, **k: set()`).

## Сохранение и GUI
- Файл рядом с книгой: `<книга>.stress_prepass.json` (`save_prepass`/`load_prepass`, атомарно, хэш текста → `stale`, `partial`). В `.gitignore`.
- Вкладка «Проверка ударений» → галочка «ранжирование по признакам» (по умолчанию вкл), столбец «Балл», признаки в подписи слова, кнопка «Сохранённый предпроход» (грузит файл, скрывает слова, уже решённые в словарях/«подтверждено»).
- Автосохранение — только поиск по ВСЕЙ книге (или если файла ещё нет): частичный поиск (поле «Главы») не затирает полный.

## Запуск вне GUI (скрипты в scratchpad)
- Windows python: пути только scratchpad, не `/tmp`; вывод кириллицы — в файл и Read (консоль cp1251). `parse_fb2(Path)` → `(title, chapters)`.
- Python с torch/silero НЕ завершается сам на выходе (висит) — в конце скрипта `sys.stdout.flush(); os._exit(0)`.
- Полная книга ≈ 4 мин (205–235 с), главы 28–29 ≈ 16 с. Запускать фоном + Monitor `until [ -f результат ]`.
- Не делать рекурсивный `grep -r .` из корня: проходит по `.venv` и висит минутами — искать по `*.py` в корне или Grep-инструментом.

## Проверка вкладки GUI без пользователя
Скрипт создаёт `AudiobookApp(initial_book=…)`, с подменами `AudiobookApp._startup_recycle_services = lambda self: None` (иначе через 0,8 с трогает сервисы) и `messagebox.show*`/`askyesno`; вкладка `app.notebook.select(i)`, события — цикл `app.update()`; потом вызывает `_sv_load_saved()`, `_sv_scan_toggle()` (ждать `app._sv_running()`), читает `sv_tree`, `sv_status_var`, `sv_sub`; в конце `app.destroy()` и `os._exit(0)`. Настройки не сохраняются (автосохранение через 60 с, destroy раньше). PIL нет — скриншот невозможен, проверяются значения виджетов, не внешний вид.

## Сверка «как надо»
Эталона нет: «правильное» = независимый корпус (`stress_corpus_ru.tsv.gz`), золото `data/stress_gold.json` и суждение по контексту. Имена и спорное решает слух пользователя; ассистент правит только очевидные ошибки в `forced_stress_words.json` / файл книги и пересинтезирует затронутые главы (`stress-listening-session`).
